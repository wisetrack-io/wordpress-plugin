# پلاگین WiseTrack برای وردپرس

> **نسخهٔ پلاگین:** 1.0.1 · **SDK داخل بسته:** WiseTrack Web SDK 2.3.2 · **پیش‌نیاز:** وردپرس 6.2+، PHP 7.4+ (برای فروشگاه: ووکامرس 8.0+) · **مجوز:** GPL-2.0-or-later
>
> 🇬🇧 English version: [`README.md`](README.md)

پلاگین رسمی وردپرس برای سامانهٔ آنالیتیکس و اتریبیوشن [WiseTrack](https://wisetrack.io/). این پلاگین
**WiseTrack Web SDK** را در بر می‌گیرد و ردیابی خودکار بازدید صفحه‌ها، رویدادهای بدون کد (قوانین رویداد،
انتخابگر دیداری، پنل‌های ویرایشگر بلاکی و المنتور)، درآمد ووکامرس و ردیابی فرم‌ها را اضافه می‌کند — سازگار با کش،
وابسته به رضایت کاربر و با ترجمهٔ کامل فارسی.

این سند مرجع کامل محصول و فنی است: نصب، راه‌اندازی، همهٔ صفحه‌ها و تنظیمات، یکپارچه‌سازی‌ها، صفحه‌سازها،
حریم خصوصی، سرعت، API توسعه‌دهنده (ویژگی‌های HTML، کلاس‌های CSS، شورت‌کد، جاوااسکریپت، PHP، قلاب‌ها، REST)
و روش build، تست و انتشار پلاگین.

## ۱. معرفی

### ۱.۱ قابلیت‌های کلیدی

| حوزه | امکانات |
|---|---|
| **راه‌اندازی** | ویزارد ۶ مرحله‌ای با آزمایش واقعی اتصال، پیش‌نمایش زندهٔ نام صفحه‌ها و تشخیص خودکار پلاگین‌ها |
| **بازدید صفحه‌ها** | خودکار با نام معنادار (مسیر / قالب / URL)، پارامترهای زمینه‌ای وردپرس، زبان WPML/Polylang، پاپ‌آپ‌ها به‌عنوان dialog، نام‌گذاری سفارشی با regex |
| **رویداد بدون کد** | ویرایشگر قانون رویداد، **انتخابگر دیداری** روی خود سایت، الگوهای آماده، رویدادهای هوشمند (لینک خروجی، دانلود، کلیک تلفن/ایمیل/واتس‌اپ/تلگرام، عمق اسکرول، زمان در صفحه) |
| **یکپارچه‌سازی‌ها** | هستهٔ وردپرس (ورود، ثبت‌نام، دیدگاه، جست‌وجو، ۴۰۴)، ووکامرس (کل قیف فروش + درآمد)، Contact Form 7، WPForms، Gravity Forms، فرم‌های Elementor Pro، Fluent Forms، پاپ‌آپ‌های Elementor Pro و Popup Maker |
| **صفحه‌سازها** | پنل اختصاصی در ویرایشگر بلاکی (Gutenberg) و المنتور؛ دستورالعمل attribute/کلاس برای Bricks، Breakdance، Oxygen، Divi، WPBakery، Beaver Builder، Thrive، Brizy |
| **توسعه‌دهنده** | ویژگی‌های `data-wt-*`، کلاس‌های `wt-ev-*`، شورت‌کد، API جاوااسکریپت با صف زودهنگام، API پی‌اچ‌پی، بیش از ۴۰ فیلتر و اکشن، REST API |
| **عملیات** | پنل اشکال‌زدایی، وضعیت در نوار مدیریت، تست‌های Site Health، برون‌بری/درون‌ریزی، پاک‌سازی کش، مهاجرت تنظیمات، به‌روزرسانی خودکار (نسخهٔ private) |
| **کیفیت** | سازگار با کش، وابسته به رضایت، بدون اطلاعات شخصی، اسکریپت بازدیدکننده کمتر از ۱۲ کیلوبایت gzip، بدون jQuery، ترجمهٔ کامل فارسی (RTL) |

### ۱.۲ معماری و نحوهٔ کار

<div dir="ltr">

```
Visitor's browser                               WordPress (PHP)
─────────────────                               ───────────────
WiseTrack SDK  (loaded async)                   Settings + Schema (validation)
wisetrack-runtime.js (< 12 KB gz, defer)        PageContext  ─► page name & params for this URL
  ├─ SDK bridge   (init, page views, events)    Rules        ─► only the rules matching this URL
  ├─ sanitizer    (mirror of SDK validation)    ServerEventQueue ◄─ WooCommerce / forms / login …
  ├─ rules engine (click, submit, visible …)    REST wisetrack/v1  (settings, rules, pending, woo)
  ├─ attributes   (data-wt-*, wt-ev-*)          Admin: wizard, dashboard, events, settings, tools
  ├─ outbox       (survives page navigation)    Editors: Gutenberg panel, Elementor controls
  ├─ pending      (pulls server-side events)
  └─ consent gate
```

</div>

**جریان یک بازدید صفحه**

1. ابتدا PHP بررسی می‌کند این درخواست باید ردیابی شود یا نه (صفحه‌های پیشخوان، ورود، پیش‌نمایش، فید، REST، iframe صفحه‌سازها، نقش‌های مستثنا و صفحه‌های «ردیابی نشود» کنار گذاشته می‌شوند).
2. نام صفحه، نام نمایشی، نوع صفحه، پارامترهای زمینه‌ای و قوانین رویداد **فقط مربوط به همین URL** در `window.WiseTrackWP.config` چاپ می‌شوند. این داده فقط به URL وابسته است، پس صفحه کاملاً قابل کش است.
3. اسکریپت runtime با `defer` در فوتر بارگذاری می‌شود، رضایت / DNT / ربات را بررسی می‌کند و سپس SDK را به‌صورت async تزریق می‌کند.
4. هر رویداد از یک مسیر واحد عبور می‌کند: قلاب `beforeSend` ← sanitizer ← تبدیل واحد پول ← آینهٔ اعتبارسنج SDK ← `trackEvent`.

**جریان یک رویداد سمت سرور** (خرید، ورود، ارسال فرم و…)

1. کد PHP رویداد را در صف کوتاه‌مدت مخصوص همان بازدیدکننده (`ServerEventQueue`) قرار می‌دهد و کوکی `wisetrack_pending` را تنظیم می‌کند.
2. در صفحهٔ بعد (یا بلافاصله پس از سیگنال موفقیت AJAX)، مرورگر `POST /wp-json/wisetrack/v1/pending/claim` را فرا می‌خواند، رویدادها را از طریق SDK می‌فرستد و با `/pending/ack` تأیید می‌کند.
3. هیچ دادهٔ مخصوص بازدیدکننده در HTML چاپ نمی‌شود — به همین دلیل پلاگین با هر نوع کش صفحه سازگار است.

## ۲. پیش از شروع

### ۲.۱ پیش‌نیازها

| مؤلفه | حداقل | توضیح |
|---|---|---|
| وردپرس | 6.2 | تک‌سایت و چندسایته |
| PHP | 7.4 | نسخهٔ 8.x پیشنهاد می‌شود |
| ووکامرس | 8.0 | فقط برای ردیابی فروشگاه؛ سازگار با HPOS و بلاک‌های سبد/تسویه‌حساب |
| مرورگر بازدیدکننده | مرورگرهای به‌روز | SDK به‌صورت پیش‌فرض برای ربات‌ها بارگذاری نمی‌شود |
| ارتباط خروجی HTTPS | `*.wisetrack.io` | باید در CSP یا فایروال مجاز باشد |

### ۲.۲ چک‌لیست

- [ ] **حساب WiseTrack** و یک اپلیکیشن ساخته‌شده برای همین وب‌سایت.
- [ ] **App Token** و **Client Secret** اپلیکیشن (پنل WiseTrack ← اپلیکیشن ← تنظیمات SDK).
- [ ] **ثبت دامنهٔ سایت** برای اپلیکیشن در پنل WiseTrack. SDK نام میزبان صفحه را با عنوان `package_name` می‌فرستد؛ دامنهٔ ثبت‌نشده خطای `Application not found` می‌گیرد.
- [ ] تصمیم دربارهٔ **روش نام‌گذاری** بازدیدها ([۸.۲](#s8-2)) و **سیاست رضایت** سایت ([۱۳](#s13)).
- [ ] یک **سایت آزمایشی (staging)** یا محیط **Sandbox** برای آزمون‌های اولیه.

> **نکته:** همیشه با **Sandbox** شروع کنید و فقط پس از دیدن دادهٔ درست به **Production** بروید ([۶](#s6)).

## ۳. نصب

### ۳.۱ از پیشخوان وردپرس (روش پیشنهادی)

1. فایل `wisetrack-<version>-private.zip` را از [آخرین انتشار](https://github.com/wisetrack-io/wordpress-plugin/releases/latest) دریافت کنید.
2. *(توصیه‌شده)* صحت فایل را با checksum منتشرشده کنار آن بررسی کنید:

<div dir="ltr">

```bash
shasum -a 256 -c wisetrack-<version>-private.zip.sha256
```

</div>

3. به **افزونه‌ها › افزودن › بارگذاری افزونه** بروید، فایل zip را انتخاب کنید، **نصب** و سپس **فعال‌سازی** را بزنید.
4. **ویزارد راه‌اندازی** خودکار باز می‌شود (فقط برای کاربری که افزونه را فعال کرده و فقط تا زمانی که سایت متصل نشده است).

### ۳.۲ با WP-CLI

<div dir="ltr">

```bash
wp plugin install /path/to/wisetrack-<version>-private.zip --activate
```

</div>

پس از فعال‌سازی با CLI، گروهی یا شبکه‌ای، ویزارد خودکار باز نمی‌شود — آن را از **WiseTrack › راه‌اندازی** باز کنید.

### ۳.۳ چندسایته (Multisite)

- برای هر سایت جداگانه یا برای کل شبکه قابل فعال‌سازی است. هر سایت تنظیمات، قوانین و اطلاعات اتصال مستقل دارد.
- هنگام فعال‌سازی، `manage_wisetrack` به نقش *administrator* هر سایت اضافه می‌شود.

### ۳.۴ فعال‌سازی چه کارهایی انجام می‌دهد

- گزینهٔ `wisetrack_settings` را با پیش‌فرض‌های امن می‌سازد (تا ذخیرهٔ اطلاعات اتصال چیزی ردیابی نمی‌شود).
- نوع نوشتهٔ خصوصی `wisetrack_rule` (قوانین رویداد) را ثبت می‌کند.
- قابلیت `manage_wisetrack` را به مدیران می‌دهد.
- منوی **WiseTrack** در پیشخوان و منوی **WiseTrack** در نوار مدیریت سایت را اضافه می‌کند.

## ۴. ویزارد راه‌اندازی

ویزارد همیشه از **WiseTrack › راه‌اندازی** در دسترس است. هر مرحله را می‌توان رد کرد و بعداً به آن برگشت.

| # | مرحله | کار |
|---|---|---|
| ۱ | **خوش‌آمد** | معرفی و محل پیدا کردن App Token و Client Secret |
| ۲ | **اتصال** | وارد کردن **App Token**، **Client Secret** و **محیط** (ابتدا *Sandbox*). **آزمایش اتصال** SDK واقعی را با همین اطلاعات راه‌اندازی و نتیجه را گزارش می‌کند؛ مثلاً: «متصل شد. SDK با این اطلاعات در ۱٫۸ ثانیه راه‌اندازی شد.» |
| ۳ | **بازدید صفحه‌ها** | روشن/خاموش بازدید خودکار، **روش نام‌گذاری** (با نمونه‌های واقعی از سایت: صفحهٔ اصلی، آخرین نوشته، یک برگه، یک محصول)، نقش‌ها و مسیرهای مستثنا |
| ۴ | **یکپارچه‌سازی‌ها** | پلاگین‌های فعال شناسایی‌شده (ووکامرس، المنتور، CF7، WPForms…) با کلید (پیشنهاد: روشن) و کلیدهای رویدادهای هوشمند |
| ۵ | **حریم خصوصی** | حالت رضایت. اگر WP Consent API یا یکی از پلاگین‌های کوکی شناخته‌شده (Complianz، CookieYes، Real Cookie Banner، Cookiebot) فعال باشد، گزینهٔ مناسب پیشنهاد می‌شود. |
| ۶ | **پایان** | چک‌لیست و میان‌برها: انتخابگر دیداری روی صفحهٔ اصلی، پنل اشکال‌زدایی، مستند توسعه‌دهنده |

**خطاهای آزمایش اتصال**

| پیام | علت | راه‌حل |
|---|---|---|
| `Application not found` | توکن اشتباه یا دامنهٔ فعلی برای اپ ثبت نشده | توکن را بررسی و دامنه را ثبت کنید. آزمایش از `localhost` معمولاً به همین دلیل شکست می‌خورد. |
| Timeout / خطای شبکه | درخواست‌های خروجی به `*.wisetrack.io` مسدود است | دامنه را در فایروال / `connect-src` در CSP مجاز کنید. |
| خطای اعتبارسنجی توکن / رمز | مقدار خالی یا نادرست | مقادیر را بدون فاصلهٔ اضافه دوباره وارد کنید. |

## ۵. بررسی صحت نصب

1. از حساب **خارج شوید** یا یک **پنجرهٔ ناشناس** باز کنید — مدیرها به‌صورت پیش‌فرض ردیابی نمی‌شوند.
2. چند صفحه از سایت را باز کنید.
3. در پنل WiseTrack (Sandbox) ظرف چند دقیقه بازدیدها با نام‌هایی مثل `/` و `/sample-page` و پارامترهای `page_type`، `post_type`، `post_id` نمایش داده می‌شوند.
4. برای دیدن داده‌های ارسالی **از مرورگر خودتان**، **پنل اشکال‌زدایی** را روشن کنید: نوار مدیریت › **WiseTrack › پنل اشکال‌زدایی**، یا افزودن `?wisetrack_debug=1` به هر آدرس ([۷.۵](#s7-5)).
5. **ابزارها › سلامت سایت** را بررسی کنید: تست‌های WiseTrack (اطلاعات اتصال، فایل SDK، محیط، پلاگین‌های بهینه‌ساز، حالت رضایت، واحد پول فروشگاه) باید موفق باشند.

**نقطهٔ وضعیت در نوار مدیریت**

| رنگ | معنی |
|---|---|
| 🟢 سبز | runtime روی این صفحه بارگذاری شده است |
| ⚪ خاکستری | نقش شما مستثناست یا صفحهٔ پیشخوان است |
| ⚫ خاموش | تنظیم نشده، بارگذاری نشده، یا صفحه «ردیابی نشود» است |

## ۶. انتقال به محیط واقعی (Sandbox ← Production)

1. در Sandbox مطمئن شوید بازدیدها، رویدادهای کلیدی و (برای فروشگاه) یک خرید آزمایشی درست ثبت می‌شوند.
2. **WiseTrack › تنظیمات › عمومی** ← **محیط: Production** ← ذخیره.
3. کش‌های صفحهٔ پشتیبانی‌شده خودکار پاک می‌شوند؛ کش CDN را خودتان پاک کنید (یا از `wisetrack_page_cache_purged` استفاده کنید).
4. پنل اشکال‌زدایی را در مرورگر خود خاموش کنید.

> سایتی که شبیه سایت اصلی است ولی هنوز به Sandbox داده می‌فرستد، هشدار Site Health و اعلان پیشخوان می‌گیرد (تشخیص با `wisetrack_is_production_site` قابل تنظیم است).

## ۷. صفحه‌های پیشخوان

منوی **WiseTrack** شامل **پیشخوان · رویدادها · تنظیمات · ابزارها · راه‌اندازی** است. همهٔ صفحه‌ها نیازمند `manage_wisetrack` هستند و هر صفحه یک تب **راهنما › توسعه‌دهندگان** با میان‌برهای کد دارد.

### ۷.۱ پیشخوان

- **وضعیت:** متصل/نامتصل، Sandbox یا Production، نسخه و منبع SDK، سلامت فایل SDK، آخرین آزمایش اتصال.
- **اقدامات سریع:** اجرای دوبارهٔ آزمایش اتصال، باز کردن انتخابگر دیداری، راهنمای پنل اشکال‌زدایی.
- **چه چیزهایی ردیابی می‌شود:** خلاصهٔ ردیابی صفحه‌ها، یکپارچه‌سازی‌ها و قوانین.
- اگر هنوز متصل نیست: **شروع / ادامهٔ راه‌اندازی**.

### ۷.۲ تنظیمات

پنج تب با لینک مستقیم: `#general`، `#pages`، `#privacy`، `#integrations`، `#advanced`. نوار ذخیرهٔ چسبان تغییرات ذخیره‌نشده را نشان می‌دهد، گزینهٔ **دور انداختن** دارد و پیش از خروج هشدار می‌دهد. خطاهای اعتبارسنجی سرور زیر همان فیلد و روی برچسب تب نمایش داده می‌شوند. مرجع: [۸](#s8).

### ۷.۳ رویدادها

قوانین رویداد با جست‌وجو، فیلتر (وضعیت، نوع trigger، منبع)، صفحه‌بندی، کلید در هر ردیف و اقدامات گروهی (فعال، غیرفعال، حذف، کپی، برون‌بری). زیر فهرست، کارت‌های فقط‌خواندنی **رویدادهای ووکامرس** و **رویدادهای هوشمند**. جزئیات: [۹](#s9).

### ۷.۴ ابزارها

برون‌بری/درون‌ریزی، بازنشانی، کلید پنل اشکال‌زدایی، اطلاعات سیستم. جزئیات: [۱۷](#s17).

<a id="s7-5"></a>

### ۷.۵ پنل اشکال‌زدایی (Debug overlay)

پنلی شناور روی سایت که **فقط برای همان مرورگر** فعال می‌شود (هیچ چیزی در HTML چاپ نمی‌شود):

- فعال‌سازی: نوار مدیریت › **WiseTrack › پنل اشکال‌زدایی**، یا `?wisetrack_debug=1`، یا `localStorage.setItem( 'wisetrack_debug', '1' )`.
- نمایش: وضعیت SDK، تایم‌لاین بازدیدها و رویدادها همراه با **تفاوت قبل و بعد از sanitizer**، پارامترها/رویدادهای حذف‌شده با دلیل، تطابق قوانین، رویدادهای سرور و لاگ‌های SDK.
- دکمه‌ها: کپی JSON، پاک کردن، هایلایت عنصرهای هدف. قابل جابه‌جایی و جمع شدن. (متن‌های این پنل عمداً انگلیسی‌اند.)

### ۸.۵ پیشرفته

| فیلد | پیش‌فرض | توضیح |
|---|---|---|
| استراتژی بارگذاری | `defer` | `defer` (پس از parse) یا `idle` (هنگام بیکاری مرورگر — کمترین اثر، شروع کمی دیرتر) |
| تأخیر شروع ردیابی | `0` ثانیه | تأخیر پیش از شروع ردیابی |
| سازگاری با بهینه‌سازها | روشن | جلوگیری از تأخیر/ادغام/minify اسکریپت‌های WiseTrack در WP Rocket، LiteSpeed، Autoptimize، SiteGround، W3TC، Perfmatters و FlyingPress؛ افزودن `data-cfasync="false"` برای Cloudflare Rocket Loader |
| سطح لاگ SDK | `warn` | `debug`، `info`، `warn`، `error`، `none` |
| نام‌گذاری سفارشی صفحه‌ها | — | قوانین regex روی مسیر (پایین را ببینید) |
| حذف داده‌ها هنگام پاک کردن افزونه | خاموش | حذف تنظیمات، قوانین و صف‌ها هنگام حذف پلاگین |

**نام‌گذاری سفارشی صفحه‌ها** نام بازدیدها را با یک regex روی مسیر تغییر می‌دهد (اولین تطابق اعمال می‌شود و SDK آن را روی `location.pathname` می‌آزماید). `$1`…`$9` گروه‌های گرفته‌شده را در نام و نام نمایشی درج می‌کنند:

| الگو | نام | نام نمایشی | `/courses/php-basics/lesson-3` ← |
|---|---|---|---|
| `^/courses/([^/]+)/lesson-(\d+)` | `course_lesson` | `$1 — lesson $2` | نام `course_lesson`، نام نمایشی `php-basics — lesson 3` |
| `^/blog/` | `blog_post` | *(خالی)* | نام `blog_post`، نام نمایشی از خود صفحه |

نام‌ها مانند هر نام صفحه‌ای پاک‌سازی می‌شوند (حداکثر ۱۵۰ نویسه) و الگوها هنگام ذخیره (PCRE) اعتبارسنجی می‌شوند.

## ۹. رویدادها: قوانین، الگوهای آماده و انتخابگر دیداری

<a id="s9-1"></a>

### ۹.۱ قواعدی که همه‌جا اعمال می‌شوند

| مورد | قاعده |
|---|---|
| نام رویداد / کلید پارامتر | به `[a-z0-9_]` تبدیل می‌شود، با حرف شروع می‌شود، حداکثر ۵۰ نویسه: `"Create Account"` ← `create_account`. نام را لاتین بنویسید؛ زبان‌های دیگر در برچسب و مقدار. |
| مقدار پارامتر | حداکثر ۱۰۰ نویسه؛ کوتیشن، `%`، `#` و HTML حذف و کلمات SQL خنثی می‌شوند (`"Update cart"` ← `update_cart`). |
| تعداد پارامتر | حداکثر ۲۵ (`wisetrack_max_event_params`) |
| محافظ اطلاعات شخصی | مقادیر شبیه ایمیل یا تلفن (از جمله موبایل ایرانی `09xxxxxxxxx`) حذف می‌شوند. هرگز اطلاعات شخصی، شناسهٔ کاربر وردپرس، نام یا مقدار فیلد هویتی فرم نفرستید. |
| کش | هرگز دادهٔ مخصوص بازدیدکننده را در HTML چاپ نکنید — از API پی‌اچ‌پی استفاده کنید ([۱۶.۶](#s16-6)). |

خود SDK رویدادهای نامعتبر را بی‌صدا دور می‌اندازد — پلاگین پیش از ارسال همه‌چیز را اعتبارسنجی می‌کند و پنل اشکال‌زدایی تغییرات یا حذف‌ها را نشان می‌دهد.

### ۹.۲ ویرایشگر رویداد

| بخش | محتوا |
|---|---|
| **رویداد** | برچسب (به هر زبانی، مثلاً «دکمهٔ خرید صفحهٔ اصلی») و نام رویداد (لاتین)؛ نام نرمال‌شده زنده نمایش داده می‌شود. |
| **Trigger** | کلیک · ارسال فرم · دیده‌شدن (با درصد) · باز شدن صفحه · عمق اسکرول · زمان در صفحه · رویداد DOM |
| **هدف** | CSS selector + **انتخاب در سایت**. گزینهٔ *شامل فرزندان* کلیک روی آیکن داخل عنصر را هم حساب می‌کند. |
| **کجا** | همهٔ صفحه‌ها، یا *فقط* / *به‌جز* با شرط‌ها: نوشته/برگه/دستهٔ مشخص، نوع نوشته، مسیر شروع‌شونده با…، regex |
| **داده** | پارامترها با تراشه‌های توکن و پیش‌نمایش زنده که از همان sanitizer مشترک عبور می‌کند |
| **درآمد** | منبع مبلغ — ثابت، attribute عنصر (مثلاً `data-price`)، متن عنصر (مثلاً `.price .amount`) یا توکن — و واحد پول |
| **دفعات ارسال** | هر بار · یک‌بار در هر بازدید صفحه · یک‌بار در هر نشست · یک‌بار برای هر بازدیدکننده، به‌علاوهٔ یادداشت خصوصی |
| **پیش‌نمایش** | payload به‌صورت JSON و اعتبارسنجی زنده (`/rules/validate`) |

### ۹.۳ نمونه‌ها

**کلیک دکمهٔ خرید پلن** — برچسب «دکمهٔ خرید پلن طلایی»، نام `click_buy_gold`، Trigger *کلیک* روی `#pricing .plan-gold .btn`، *فقط* مسیر `/pricing`، پارامترهای `button_text = {{element.text}}` و `plan = gold`، درآمد ثابت `490000` با واحد `IRT` (ارسال به‌صورت `4900000 IRR`)، *یک‌بار در هر بازدید صفحه*.

**دیده شدن بخش قیمت‌ها** — Trigger *دیده‌شدن* ۵۰٪ روی `#pricing`، نام `pricing_seen`، یک‌بار در هر نشست.

**رویداد سفارشی قالب** — Trigger *رویداد DOM* با نام `my-theme:signup`؛ قالب
`document.dispatchEvent( new CustomEvent( 'my-theme:signup', { detail: { plan: 'pro' } } ) )` را اجرا می‌کند و `detail` به پارامترها تبدیل می‌شود (رویدادهای jQuery هم‌نام هم شنیده می‌شوند).

### ۹.۴ الگوهای آماده (Presets)

با یک کلیک یک قانون ازپیش‌پرشده ساخته می‌شود: لینک خروجی · دانلود فایل · کلیک تلفن · کلیک ایمیل · کلیک واتس‌اپ (`wa.me`، `api.whatsapp.com`، `whatsapp://`) · کلیک تلگرام (`t.me`، `tg://`) · کلیک اینستاگرام · اسکرول ۵۰٪ / ۹۰٪ · ۳۰ / ۶۰ ثانیه در صفحه · صفحهٔ ۴۰۴ · صفحهٔ نتایج جست‌وجو · ارسال فرم (عمومی) · «ارسال فرم — &lt;نام پلاگین&gt;» برای هر پلاگین فرم فعال.

### ۹.۵ انتخابگر دیداری (Visual Picker)

**راه‌های باز کردن:** نوار مدیریت › **WiseTrack › انتخاب یک عنصر برای ردیابی** (روی هر صفحهٔ سایت) · لینک ردیف **ردیابی عنصرها** در فهرست نوشته‌ها/برگه‌ها · **باز کردن انتخابگر دیداری** در پیشخوان · **انتخاب در سایت** در ویرایشگر رویداد.

**روند کار**

1. با حرکت ماوس دور عنصرها کادر و برچسب `tag#id.class (N)` نمایش داده می‌شود.
2. کلیک = انتخاب (لینک‌ها و فرم‌ها اجرا نمی‌شوند). در حالت **مرور** یا با نگه داشتن `Alt` صفحه عادی کار می‌کند (مثلاً برای باز کردن منو).
3. صفحه‌کلید: `Esc` لغو، `↑` / `↓` والد / فرزند، `Enter` رفتن به فیلد نام؛ تراشه‌های breadcrumb هم کار می‌کنند.
4. پنل کناری (در RTL سمت چپ، در موبایل به‌صورت bottom sheet):
   - selector قابل ویرایش با تعداد تطابق زنده و **امتیاز پایداری** (بالا / متوسط / پایین، با دلیل)؛
   - **انتخاب موارد مشابه** (مثلاً همهٔ دکمه‌های «افزودن به سبد» یک گرید محصول)؛
   - برچسب و نام پیشنهادی (متن فارسی نویسه‌گردانی می‌شود: «خرید» ← `click_kharid`)؛
   - trigger (کلیک / ارسال فرم / دیده‌شدن) — برای عنصرهای داخل فرم: «به‌جای آن ارسال فرم را ردیابی کن»؛
   - دامنه: همین صفحه / همهٔ صفحه‌های این نوع / کل سایت / شرایط فعلی / پیشرفته؛
   - پارامترها با مقدار زنده، درآمد (حتی از متنی مثل «۴۹۰٬۰۰۰ تومان» ← 490000)، دفعات ارسال؛
   - **پیش‌نمایش payload**؛ **ذخیره** · **ذخیره و انتخاب بعدی** · **باز کردن در ویرایشگر کامل**.
5. **نمایش رویدادهای موجود** عنصرهای دارای قانون فعال را با badge نشان می‌دهد، امکان ویرایش/غیرفعال کردن می‌دهد و قوانینی را که «در این صفحه پیدا نشد» فهرست می‌کند.
6. پس از ذخیره، صفحه‌های باز رویدادها در پیشخوان خودکار به‌روز می‌شوند.

> عنصرهای داخل iframe قابل انتخاب نیستند. برای selector پایدار به عنصر `data-wt-event`، یک `id` خوانا یا `data-testid` بدهید.

## ۱۱. یکپارچه‌سازی‌ها

*تنظیمات › یکپارچه‌سازی‌ها* همهٔ پلاگین‌های پشتیبانی‌شدهٔ فعال را فهرست می‌کند. هر یکپارچه‌سازی فقط وقتی اجرا می‌شود که **پلاگینش فعال و خود یکپارچه‌سازی روشن باشد** (ویزارد آن را پیشنهاد می‌کند). هر رویداد قابل خاموش کردن یا تغییر نام است.

### ۱۱.۱ هستهٔ وردپرس

| رویداد | نام پیش‌فرض | پارامترها | زمان تحویل |
|---|---|---|---|
| ورود | `login` | `method: wp` | بازدید بعدی (صف سرور) |
| ثبت‌نام | `sign_up` | `method: wp` | بازدید بعدی — فقط ثبت‌نام خودِ کاربر (فرم ثبت‌نام، تسویه‌حساب)؛ نه حسابی که کاربر واردشده، WP-CLI یا cron می‌سازد |
| دیدگاه | `comment_submit` | `post_id`، `post_type`، `comment_status` (`approved`/`pending`) | بازدید بعدی؛ هرگز اسپم، متن یا اطلاعات نویسنده |
| جست‌وجو | `search` | `results_count` (+ `search_term` فقط با «ارسال عبارت جست‌وجو») | صفحهٔ نتایج |
| صفحه پیدا نشد | `page_not_found` | `path` | صفحهٔ ۴۰۴ |

استثنای نقش‌ها بر اساس کاربری اعمال می‌شود که وارد می‌شود / ثبت‌نام می‌کند؛ درخواست‌های REST ناشناس (پلاگین‌های فرم بدون nonce) هم بازدیدکنندهٔ واردشده را از روی کوکی احراز هویت تشخیص می‌دهند.

### ۱۱.۲ فرم‌ها

| پلاگین | هوک سرور (منبع رویداد) | سیگنال مرورگر (دریافت فوری) |
|---|---|---|
| Contact Form 7 | `wpcf7_mail_sent` | `wpcf7mailsent` |
| WPForms | `wpforms_process_complete` | `wpformsAjaxSubmitSuccess` |
| Gravity Forms | `gform_after_submission` (بدون اسپم) | `gform_confirmation_loaded` |
| Elementor Pro Forms | `elementor_pro/forms/new_record` | `submit_success` |
| Fluent Forms | `fluentform/submission_inserted` (+ نام قبل از 5.0) | `fluentform_submission_success` |

- فقط ارسال **موفق** شمرده می‌شود؛ رویداد `form_submit` با `form_plugin` (شناسهٔ یکپارچه‌سازی)، `form_id`، `form_name`.
- هوک سرور رویداد را صف می‌کند؛ فرم‌های AJAX دریافت فوری را فعال می‌کنند و فرم‌هایی که صفحه را دوباره بارگذاری می‌کنند در بازدید بعدی تحویل می‌دهند. هر ارسال فقط یک‌بار صف می‌شود (`plugin:form_id:submission`)، پس سیگنال مرورگر هرگز رویداد دوم نمی‌سازد.
- **تنظیم هر فرم** (*تنظیمات › یکپارچه‌سازی‌ها › فرم‌ها*): روشن/خاموش، نام سفارشی (مثلاً `quote_request`) و پارامترهای اضافه — متن ثابت یا `{{form.field:NAME}}` / `{{form.id}}`. نام فیلد: نام تگ در CF7، شناسه یا برچسب فیلد در WPForms، شناسه / برچسب مدیریتی / نام پارامتر در Gravity، شناسهٔ فیلد در المنتور، نام input در Fluent.
- **هرگز ارسال نمی‌شوند:** مقدار فیلدهای رمز، ایمیل، تلفن، hidden و file؛ فیلدهایی که نامشان شخصی به نظر می‌رسد (`pass|mail|phone|mobile|tel|card|cvv|national|melli|nonce|token|secret`)؛ و هر مقدار شبیه ایمیل یا تلفن.
- رویداد اضافهٔ مخصوص یک صفحه لازم دارید؟ *رویدادها › الگوهای آماده › ارسال فرم — &lt;پلاگین&gt;* قانونی روی سیگنال موفقیت مرورگرِ همان پلاگین می‌سازد.

*نمونه:* فرم CF7 «درخواست مشاوره» (شناسهٔ 123) ← نام `consult_request`، پارامتر `service = {{form.field:service-type}}` (یک select غیرشخصی).

### ۱۱.۳ ووکامرس

نیازمند ووکامرس 8.0 به بالا؛ سازگار با HPOS و بلاک‌های سبد/تسویه‌حساب (سفارش‌ها فقط از طریق CRUD ووکامرس تغییر می‌کنند).

| رویداد | نام پیش‌فرض | پارامترها | منبع |
|---|---|---|---|
| مشاهدهٔ محصول | `view_item` | `product_id`، `product_sku`، `product_cat` (دستهٔ اصلی Yoast/Rank Math، وگرنه اولین دسته)، `price`، `currency` | صفحهٔ محصول (دادهٔ URL همراه صفحه) |
| افزودن به سبد | `add_to_cart` | `product_id`، `variation_id`؟، `quantity`، `price` (واحد)، `currency` | `woocommerce_add_to_cart` (AJAX کلاسیک، فرم محصول، Store API/بلاک‌ها) ← صف سرور |
| حذف از سبد | `remove_from_cart` | `product_id`، `variation_id`؟، `quantity` | `woocommerce_cart_item_removed` ← صف سرور |
| مشاهدهٔ سبد | `view_cart` | `item_count`، `cart_total`، `currency` | صفحهٔ سبد (برگهٔ تنظیم‌شده، بلاک Cart یا `[woocommerce_cart]`)؛ مبالغ از `GET woo/cart-summary` |
| شروع تسویه‌حساب | `begin_checkout` | مانند `view_cart` | صفحهٔ تسویه‌حساب (نه order-received / order-pay) |
| خرید | `purchase` (درآمد) | `order_id`، `item_count`، `payment_method`، `shipping_method`؟، `coupon_used` | توضیح در ادامه |

- پارامترهای مبلغ (`price`، `cart_total`) مانند درآمد تبدیل می‌شوند (تومان ← ریال) و `currency` حاصل را دارند.
- رویدادهای سبد بلافاصله پس از رویدادهای مرورگرِ ووکامرس دریافت می‌شوند: jQuery `added_to_cart`، `removed_from_cart`، `updated_cart_totals`، DOM `wc-blocks_added_to_cart`، `wc-blocks_removed_from_cart` و (نه در صفحهٔ تسویه) `wc-blocks_store_sync_required`. در غیر این صورت با بازدید بعدی می‌رسند.
- اسکریپت `build/integrations.js` فقط در صفحه‌های محصول، سبد و تسویه‌حساب بارگذاری می‌شود.

**خرید — دقیقاً یک‌بار برای هر سفارش**

1. **ساخت سفارش** (`woocommerce_checkout_order_processed`، `woocommerce_store_api_checkout_order_processed`): شناسهٔ بازدیدکننده روی سفارش ذخیره می‌شود (`_wisetrack_visitor_sid`). نقش‌های مستثنا شناسه‌ای نمی‌گیرند.
2. **آماده شدن** (`_wisetrack_purchase_ready`) طبق تنظیم *زمان ثبت خرید*:
   - `paid` *(پیش‌فرض)* — اولین مورد از `woocommerce_payment_complete` / وضعیت `processing` / `completed` (در انتظار بررسی، ناموفق، لغوشده ← هیچ)؛
   - `thankyou` — هنگام ساخت سفارش؛ ارسال فقط از صفحهٔ تشکر (سفارش ناموفق هرگز).
3. **یک‌بار صف می‌شود** (`_wisetrack_purchase_queued`) برای بازدیدکنندهٔ ذخیره‌شده — حتی اگر webhook درگاه پرداخت آن را آماده کرده باشد. بازدیدکننده آن را در صفحهٔ تشکر یا بازدید بعدی دریافت می‌کند (تا وقتی پرداخت در انتظار است، مرورگر مرتب می‌پرسد). صفحهٔ تشکر کلید سفارش را بررسی می‌کند، اگر سفارش بازدیدکننده نداشته باشد او را منتسب می‌کند و خریدی را که صف شده ولی تأیید نشده دوباره عرضه می‌کند؛ باز کردن لینک order-received در مرورگر دیگر چیزی نمی‌فرستد.
4. **تأیید** توسط مرورگر ← `_wisetrack_purchase_sent` + یادداشت خصوصی سفارش **«WiseTrack: purchase event sent.»** (فیلتر `wisetrack_order_note`). uid آیتم از شناسهٔ سفارش ساخته می‌شود و مرورگر uidهای تحویل‌شده به SDK را به خاطر می‌سپارد، پس تحویل مجدد هرگز دوبار ارسال نمی‌شود.

**درآمد و واحد پول**

- **مبنای درآمد:** *جمع کل سفارش* یا *جمع جزء* (اقلام پس از تخفیف، بدون مالیات، حمل‌ونقل و هزینه‌ها)؛ فیلتر `wisetrack_revenue_amount`؛ مبلغ به واحد پول **سفارش**.
- **واحدهای ایرانی ← ریال (`IRR`)**، گرد شده به عدد صحیح: `IRT` ×۱۰، `IRHT` (هزار تومان) ×۱۰٬۰۰۰، `IRHR` (هزار ریال) ×۱٬۰۰۰. کدهای افزونه‌های واحد پول ایرانی (`TOMAN`، `TMN`، `IRTOMAN`، `RIAL`، `HTOMAN`…) و نمادهای فارسی (`تومان`، `ریال`، `هزار تومان`…) شناخته می‌شوند.
- **سایر کدهای پشتیبانی‌نشده:** یک ردیف در *تبدیل واحد پول* اضافه کنید، مثلاً `{"XYZ": {"to": "USD", "factor": 1}}`. اگر باز هم پشتیبانی نشود، خرید بدون درآمد ارسال، Site Health هشدار و *ووکامرس › وضعیت › لاگ‌ها* (منبع `wisetrack`) آن را ثبت می‌کند.
- صفحهٔ تنظیمات یک نمونهٔ زنده نشان می‌دهد: «۱٬۲۵۰٬۰۰۰ تومان ← 12,500,000 IRR».

ذخیره‌سازی صف در سایت‌های ووکامرسی: صف هر بازدیدکننده یک ردیف مستقل در جدول session ووکامرس است (`session_key` با پیشوند `wt…`) که ووکامرس خودش پاک‌سازی می‌کند — هرگز داخل دادهٔ session مشتری.

### ۱۱.۴ پاپ‌آپ‌ها

پاپ‌آپ‌های Elementor Pro (`elementor/popup/show`) و Popup Maker (`pumAfterOpen`): هر باز شدن یک صفحهٔ dialog با نام `popup:<id>` و عنوان پاپ‌آپ به‌عنوان نام نمایشی. رویداد اختیاری `popup_open` (`popup_id`، `popup_name`)، پیش‌فرض خاموش. `build/integrations.js` (کمتر از ۱ کیلوبایت gzip) فقط جایی بارگذاری می‌شود که پلاگین پاپ‌آپ اسکریپت خودش را بارگذاری کند. المنت‌های بومی `<dialog>` را خود SDK ردیابی می‌کند.

## ۱۲. صفحه‌سازها

### ۱۲.۱ ویرایشگر بلاکی (Gutenberg)

هر بلاک یک پنل **WiseTrack** دارد: نام رویداد (نرمال‌شده به‌صورت زنده)، *زمان ارسال* (کلیک، دیده‌شدن، ارسال فرم داخل بلاک — فقط بلاک‌های فرم‌مانند، باز شدن صفحه)، پارامترها با تراشهٔ توکن، *دفعات ارسال* و «صفحه هنگام کلیک» برای بلاک‌های تب‌مانند (تب، آکاردئون، details، مراحل). آیکن نمودار در نوار ابزار بلاک نشان می‌دهد بلاک رویداد دارد؛ *انتخاب در سایت* انتخابگر را روی صفحهٔ منتشرشده باز می‌کند.

تنظیمات در attribute بلاکی به نام `wisetrack` ذخیره می‌شود که فقط در کامنت بلاک است (`<!-- wp:button {"wisetrack":{"event":"buy"}} -->`). HTML ذخیره‌شده دست نمی‌خورد، پس محتوا هرگز «نامعتبر» نمی‌شود و با حذف WiseTrack اثری نمی‌ماند. هنگام رندر، اولین تگ HTML بلاک ویژگی‌های `data-wt-*` متناظر را می‌گیرد (بلاک‌های ایستا و پویا؛ ویژگی‌هایی که از قبل در markup هستند اولویت دارند).

### ۱۲.۲ المنتور (رایگان و Pro)

تب *پیشرفته* ← بخش **WiseTrack** روی هر ویجت، سکشن، ستون و کانتینر: نام رویداد، *زمان ارسال*، پارامترها (repeater، توکن مجاز)، *دفعات ارسال*. ویژگی‌ها روی wrapper عنصر چاپ می‌شوند؛ برای ویجت دکمه روی خود لینک. روشن/خاموش کردن یکپارچه‌سازی کش المنتور را پاک می‌کند. در المنتور رایگان می‌توانید از قرارداد کلاس و در المنتور Pro از *Attributes* هم استفاده کنید.

هوک‌های استفاده‌شده (المنتور 4.3): `elementor/element/common/_section_style/after_section_end` (ویجت‌ها)، `elementor/element/section/section_advanced/after_section_end`، `elementor/element/column/section_advanced/after_section_end`، `elementor/element/container/section_layout/after_section_end`، `elementor/frontend/before_render`.

### ۱۲.۳ سایر صفحه‌سازها

کنترل اختصاصی WiseTrack ندارند — هر جا صفحه‌ساز attribute سفارشی دارد از آن استفاده کنید، وگرنه از قرارداد کلاس ([۱۶.۲](#s16-2))، یا انتخابگر دیداری روی صفحهٔ منتشرشده.

| صفحه‌ساز | مراحل |
|---|---|
| **Bricks** (attribute) | عنصر ← *Style* ← *Attributes* ← *Add attribute* ← نام `data-wt-event`، مقدار `signup_click` (اختیاری: `data-wt-param-plan` = `pro`، `data-wt-trigger` = `visible`) |
| **Breakdance / Oxygen 6** (attribute) | عنصر ← *Settings* ← *Advanced* ← *Attributes* ← *Add* ← `data-wt-event` = `signup_click` |
| **Oxygen 4** (attribute) | عنصر ← *Advanced* ← *Attributes* ← *Add attribute* ← `data-wt-event` = `signup_click` |
| **Elementor Pro** (attribute) | ویجت ← *Advanced* ← *Attributes*، هر خط یکی: `data-wt-event\|signup_click`، `data-wt-param-plan\|pro` |
| **Elementor رایگان** (کلاس) | ویجت ← *Advanced* ← *CSS Classes* ← `wt-ev-signup_click wt-p-plan-pro` |
| **WPBakery** (کلاس) | عنصر ← *Design Options* / *General* ← *Extra class name* ← `wt-ev-signup_click` (+ `wt-p-plan-pro`) |
| **Divi** (کلاس) | ماژول ← *Advanced* ← *CSS ID & Classes* ← *CSS Class* ← `wt-ev-signup_click` (دیده‌شدن: `wt-ev-pricing_seen--visible`) |
| **Beaver Builder** (کلاس) | ماژول ← *Advanced* ← *HTML Element* ← *Class* ← `wt-ev-signup_click` |
| **Thrive Architect / Brizy** (کلاس) | عنصر ← *HTML attributes* / *Advanced* ← *CSS class* ← `wt-ev-signup_click` |

آدرس‌های ویرایشگر/پیش‌نمایش که هرگز SDK بارگذاری نمی‌کنند: `elementor-preview`، `fl_builder`، `et_fb`، `ct_builder`، `oxygen=builder`، `oxygen_iframe`، `bricks=run`، `vc_editable`، `vcv-editable`، `tve`، `brizy-edit`، `brizy-edit-iframe`، `breakdance=builder`، `breakdance_iframe`، `fb-edit` (فیلتر `wisetrack_builder_preview_params`).

## ۱۳. حریم خصوصی و رضایت

### ۱۳.۱ حالت‌های رضایت

| حالت | رفتار | کاربرد |
|---|---|---|
| `off` | ردیابی بلافاصله شروع می‌شود | الزام رضایت برای مخاطبان شما وجود ندارد |
| `wp_consent_api` | تا تأیید دستهٔ تعیین‌شده (پیش‌فرض `statistics`) SDK **اصلاً بارگذاری نمی‌شود** و بلافاصله پس از آن بارگذاری می‌شود | Complianz، CookieYes، Real Cookie Banner، Cookiebot یا هر پلاگین سازگار با WP Consent API |
| `custom` | منتظر `WiseTrackWP.consent( true )` می‌ماند؛ انتخاب در `localStorage` ذخیره می‌شود | بنر اختصاصی خودتان |

- لغو رضایت (`consent( false )`) تابع `flush()` در SDK را اجرا و ردیابی را متوقف می‌کند.
- پیش از رضایت، رویدادهای مرورگر فقط در حافظه‌اند و آیتم‌های صف سرور منتظر می‌مانند. رضایت و DNT در مرورگر تعیین می‌شوند.

<div dir="ltr">

```js
// Custom banner (consent mode "custom")
document.querySelector( '#accept-cookies' ).addEventListener( 'click', () => WiseTrackWP.consent( true ) );
document.querySelector( '#reject-cookies' ).addEventListener( 'click', () => WiseTrackWP.consent( false ) );
```

</div>

### ۱۳.۲ حفاظت از داده در طراحی

- هیچ شناسهٔ کاربر وردپرس، نام، ایمیل، تلفن، hash یا `customDeviceId` ارسال نمی‌شود.
- محافظ اطلاعات شخصی مقادیر شبیه ایمیل و تلفن را از همهٔ پارامترها حذف می‌کند (سمت سرور با `wisetrack_allow_param_value` می‌توان عمداً یکی را مجاز کرد).
- پارامترهای حساس نشانی از URL و توکن‌ها حذف می‌شوند (`wisetrack_sensitive_query_params`).
- عبارت جست‌وجو فقط با فعال‌سازی صریح ارسال می‌شود.
- مدیرها به‌صورت پیش‌فرض مستثنا، ربات‌ها فیلتر و DNT/GPC اختیاری است.
- متن پیشنهادی به **راهنمای سیاست حریم خصوصی** وردپرس افزوده می‌شود — WiseTrack را در سیاست حریم خصوصی سایت ذکر کنید.

## ۱۴. کش، سرعت و سازگاری

### ۱۴.۱ کش صفحه

- خروجی HTML فقط دادهٔ وابسته به URL دارد ← هر صفحه برای همه قابل کش است.
- قوانین و تنظیمات در صفحه چاپ می‌شوند. وقتی تغییر کنند، WiseTrack کش صفحهٔ WP Rocket، LiteSpeed Cache، W3 Total Cache، SiteGround Optimizer، WP Super Cache، FlyingPress، WP Fastest Cache، Hummingbird، Cache Enabler، Breeze و Nginx Helper را یک‌بار در پایان درخواست پاک می‌کند (`wisetrack_purge_page_cache` آن را خاموش می‌کند). برای کش‌ها و CDNهای دیگر از `wisetrack_page_cache_purged` استفاده کنید.

### ۱۴.۲ پلاگین‌های بهینه‌ساز

با گزینهٔ *سازگاری با بهینه‌سازها* (`optimization_compat`، روشن)، به بهینه‌سازها گفته می‌شود اسکریپت‌های WiseTrack را به تأخیر نیندازند، defer، ادغام یا minify نکنند؛ تگ‌ها همچنین `data-cfasync="false"` (Cloudflare Rocket Loader)، `data-no-optimize`، `data-no-defer` و `data-no-minify` دارند.

### ۱۴.۳ سرعت

| مورد | مقدار |
|---|---|
| runtime بازدیدکننده | کمتر از ۱۲ کیلوبایت gzip، `defer`، فوتر، بدون jQuery |
| SDK | حدود ۵۰ کیلوبایت gzip، بارگذاری async پس از رندر |
| LCP / CLS | یکسان با و بدون پلاگین (Lighthouse) |
| TBT موبایل | حدود ۹۰ میلی‌ثانیه ناشی از راه‌اندازی SDK روی موبایل کند شبیه‌سازی‌شده (دسکتاپ: ۰) |
| preload SDK | خاموش (FCP/LCP را حدود ۱۵۰ میلی‌ثانیه عقب می‌انداخت)؛ با `wisetrack_preload_sdk` روشن می‌شود |

در سایت‌های بسیار حساس به سرعت، **استراتژی بارگذاری: idle** را انتخاب کنید.

درخواست‌های `wisetrack.io`، `/wp-json/wisetrack/v1/pending/*` و `/wp-json/wisetrack/v1/woo/*` را هرگز کش نکنید — **NetworkOnly**.

### ۱۴.۶ چندزبانه

با WPML یا Polylang زبان صفحه به بازدید اضافه می‌شود؛ با روش `template` یا نام‌گذاری سفارشی، نام صفحه‌ها بین زبان‌ها ثابت می‌ماند.

---

<a id="s15"></a>

## ۱۵. امنیت و سطح دسترسی

- همهٔ صفحه‌ها و مسیرهای REST مدیریتی نیازمند **`manage_wisetrack`** و nonce `wp_rest` هستند. برای دادن دسترسی به نقش دیگر از ویرایشگر نقش استفاده کنید یا آن را با `wisetrack_capability` تغییر دهید.
- انتخابگر دیداری nonce اختصاصی دارد؛ بدون آن، درخواست بدون پارامترهای انتخابگر به همان آدرس ریدایرکت می‌شود ([۱۶.۱۰](#s16-10)).
- مسیرهای عمومی (`/pending/*`، `/woo/cart-summary`): کوکی HttpOnly بازدیدکننده، بررسی هم‌دامنه بودن `Origin`/`Referer`، محدودیت نرخ (هر بازدیدکننده ۳۰ در دقیقه، هر IP ۱۲۰ در دقیقه؛ خلاصهٔ سبد ۶۰ در دقیقه برای هر IP)، محدودیت حجم بدنه و `Cache-Control: no-store`.
- ورودی‌ها از یک schema مرکزی عبور می‌کنند، خروجی در آخرین لحظه escape می‌شود، JSON درون‌خطی با `JSON_HEX_*` است و regexها اعتبارسنجی و محدود می‌شوند؛ بدون `eval` / `new Function`.
- پشت reverse proxy، IP واقعی کاربر را با `wisetrack_client_ip` و Originهای مجاز اضافه را با `wisetrack_pending_allowed_hosts` تعیین کنید.

> **توجه:** **Client Secret** در SDK مرورگر ناگزیر در صفحه حاضر است. در رابط کاربری مخفی است و در برون‌بری فقط با انتخاب شما می‌آید — آن را یک اطلاعات اتصال عمومی کلاینت بدانید.

# بخش دوم — مرجع توسعه‌دهنده

<a id="s16"></a>

## ۱۶. مرجع توسعه‌دهنده

هر کاری که **بدون** صفحهٔ رویدادها می‌توان انجام داد. همهٔ این روش‌ها تابع قواعد بخش [۹.۱](#s9-1) هستند؛ پنل اشکال‌زدایی را روشن کنید تا هر رویداد، تغییرات sanitizer و دلیل حذف‌ها را ببینید.

### ۱۶.۱ ویژگی‌های HTML

در قالب‌ها، «ویژگی‌های اضافه»ی بلاک‌ها، فیلدهای attribute سفارشی صفحه‌سازها (Bricks، Breakdance، Oxygen…) و هر جایی که markup را کنترل می‌کنید کار می‌کنند. به‌صورت پیش‌فرض فعال‌اند (*تنظیمات › یکپارچه‌سازی‌ها › ویژگی‌ها و کلاس‌های HTML*، کلید `attributes_enabled`).

<div dir="ltr">

```html
<a href="/pricing" data-wt-event="pricing_click" data-wt-param-plan="pro" data-wt-param-position="hero">Pricing</a>

<form data-wt-event="newsletter_signup" data-wt-trigger="submit">…</form>

<section data-wt-event="pricing_seen" data-wt-trigger="visible" data-wt-once="page">…</section>

<button data-wt-event="buy_plan" data-wt-revenue="490000" data-wt-currency="IRT"
        data-wt-params='{"plan":"gold"}'>Buy</button>

<button data-wt-screen="settings_billing" data-wt-screen-display="Billing" data-wt-screen-type="other">Billing tab</button>

<div data-wt-no-track>…rules, attributes, classes and smart events inside are ignored…</div>
```

</div>

| ویژگی | معنی |
|---|---|
| `data-wt-event` | نام رویداد |
| `data-wt-trigger` | `click` (پیش‌فرض) · `submit` (روی `<form>`) · `visible` (۵۰٪ دیده‌شدن) · `load` (باز شدن صفحه) |
| `data-wt-param-<key>` | یک پارامتر؛ کلید kebab به snake تبدیل می‌شود (`data-wt-param-button-text` ← `button_text`) |
| `data-wt-params` | شیء JSON پارامترها (ادغام می‌شود؛ `data-wt-param-*` اولویت دارد) |
| `data-wt-revenue` | مبلغ درآمد (`490000`، `"1,250,000"`؛ ارقام فارسی هم مجاز است) |
| `data-wt-currency` | کد واحد پول؛ پیش‌فرض: واحد سایت (ووکامرس). `IRT` ← `IRR` ×۱۰، `IRHT` ×۱۰٬۰۰۰، `IRHR` ×۱٬۰۰۰ |
| `data-wt-once` | `page` · `session` · `visitor` — حداکثر یک‌بار در هر بازدید صفحه / نشست مرورگر / بازدیدکننده |
| `data-wt-screen` | نام صفحهٔ دستی (تب‌ها، مراحل)؛ پیش‌فرض روی کلیک، با `data-wt-trigger="load"` هنگام باز شدن |
| `data-wt-screen-display` | نام نمایشی صفحه |
| `data-wt-screen-type` | `other` (پیش‌فرض) · `page` · `dialog` · `bottom_sheet` · `webview` |
| `data-wt-no-track` | خارج کردن یک بخش کامل از ردیابی |

کلیک داخل یک عنصر برای نزدیک‌ترین والد دارای `data-wt-event` حساب می‌شود. مقدار پارامتر می‌تواند [توکن](#s16-5) داشته باشد، مثلاً `data-wt-param-label="{{element.text}}"`.

<a id="s16-2"></a>

### ۱۶.۲ قرارداد کلاس‌های CSS

برای صفحه‌سازهایی که فقط اجازهٔ افزودن کلاس می‌دهند (WPBakery، Divi، Beaver Builder… — [۱۲.۳](#s12)):

<div dir="ltr">

```html
<a class="button wt-ev-signup_click wt-p-plan-pro wt-p-position-hero">Sign up</a>
<section class="wt-ev-pricing_seen--visible">…</section>
```

</div>

- `wt-ev-<event_name>` ← رویداد روی کلیک.
- `wt-ev-<event_name>--visible` ← رویداد هنگام دیده شدن عنصر.
- `wt-p-<key>-<value>` ← پارامتر ثابت (`key` تا اولین `-` است؛ فقط مقادیر ساده).

### ۱۶.۳ شورت‌کدها

<div dir="ltr">

```text
[wisetrack_event name="lead" plan="pro"]
```

</div>

رویداد `lead` با `plan=pro` را **هنگام باز شدن صفحه** می‌فرستد (یک `<span>` خالی و مخفی چاپ می‌کند).

<div dir="ltr">

```text
[wisetrack_event name="cta_click" plan="pro"]Click me[/wisetrack_event]
```

</div>

محتوا را در یک `<span>` می‌پیچد و روی کلیک ارسال می‌کند (یا با `trigger="visible"`).

<div dir="ltr">

```text
[wisetrack_screen name="checkout_step_2" display="Shipping" type="other"]
```

</div>

صفحهٔ دستی هنگام باز شدن.

ویژگی‌های رزرو: `name`، `trigger`، `once` (`page|session|visitor`)، `revenue`، `currency`، `params` (JSON)، `display`، `type`. هر ویژگی دیگر پارامتر می‌شود.

### ۱۶.۴ API جاوااسکریپت

اسکریپت runtime به‌صورت deferred در فوتر بارگذاری می‌شود. فراخوانی‌های پیش از آماده شدن در یک صف قرار می‌گیرند — این قطعه را در `<head>` قالب (یا هر اسکریپت زودتری) بگذارید و هر جا خواستید استفاده کنید:

<div dir="ltr">

```html
<script>
	window.wisetrackQueue = window.wisetrackQueue || [];
	wisetrackQueue.push( [ 'track', 'video_play', { video_id: 'intro' } ] );
</script>
```

</div>

دستورهای صف: `track`، `trackRevenue`، `trackScreen`، `consent`، `ready`، `on`، `off`، `pullPending`؛ تابعی که در صف push شود روی `ready` اجرا می‌شود.

<div dir="ltr">

```js
WiseTrackWP.ready( ( api ) => { /* SDK initialized and enabled */ } );

WiseTrackWP.track( 'signup', { method: 'google' } );
WiseTrackWP.trackRevenue( 'purchase', 1250000, 'IRT', { order_id: 'A-1' } ); // currency optional → 12500000 IRR
WiseTrackWP.trackScreen( { name: 'checkout_step_2', displayName: 'Shipping', type: 'other', params: {} } );

WiseTrackWP.on( 'beforeSend', ( payload ) => {
	if ( payload.name === 'internal_test' ) {
		return false; // cancel
	}
	return { ...payload, params: { ...payload.params, theme: 'dark' } }; // modify
} );
WiseTrackWP.on( 'sent', ( event ) => console.log( 'sent', event ) );
WiseTrackWP.on( 'dropped', ( info ) => console.warn( info.reason, info ) );

WiseTrackWP.consent( true );   // consent mode "custom": load/allow; false revokes (flush + stop)
WiseTrackWP.status();          // idle | waiting_consent | loading | ready | blocked | failed | revoked
WiseTrackWP.pullPending();     // fetch events queued by PHP for this visitor now (e.g. after your AJAX call)
WiseTrackWP.sdk;               // raw WiseTrackSDK namespace once ready (null before)
WiseTrackWP.config;            // the page config printed by PHP (rules, page context…)

// Without the API object:
document.dispatchEvent( new CustomEvent( 'wisetrack:track', { detail: { name: 'quiz_done', params: { score: 7 } } } ) );

// Emitted by the runtime:
document.addEventListener( 'wisetrack:ready', ( e ) => {} );     // detail: { version }
document.addEventListener( 'wisetrack:deeplink', ( e ) => {} );  // detail: { uri, isDeferred }
```

</div>

رویدادهایی که پیش از فعال شدن SDK (یا از کلیکی که صفحه را ترک می‌کند) رخ می‌دهند در `sessionStorage.wisetrack_outbox` نگه داشته (حداکثر ۵۰ مورد، ۱۰ دقیقه) و در صفحهٔ بعد تحویل داده می‌شوند.

<a id="s16-5"></a>

### ۱۶.۵ توکن‌ها

مقدار پارامترِ قوانین رویداد، ویژگی‌ها و ویرایشگر رویداد می‌تواند توکن پویا داشته باشد که در مرورگر بازدیدکننده جایگزین و سپس پاک‌سازی می‌شود:

| توکن | مقدار |
|---|---|
| `{{element.text}}` | متن عنصر (بدون فاصله‌های اضافه؛ برای دکمه‌ها value آن‌ها) |
| `{{element.attr:NAME}}` | مقدار attribute (`value` فیلدهای فرم رد می‌شود) |
| `{{element.data:NAME}}` | ویژگی `data-NAME` |
| `{{element.href}}` | آدرس لینک بدون query string و hash (`mailto:`/`tel:` رد می‌شوند) |
| `{{element.id}}` | id عنصر |
| `{{page.path}}` · `{{page.title}}` · `{{page.post_id}}` · `{{page.post_type}}` · `{{page.type}}` | دادهٔ صفحه (`page.type` = نامک قالب مثل `single_product`، `404`) |
| `{{url.query:NAME}}` | پارامتر URL (برای پارامترهای حساس رد می‌شود: `token`، `password`، `email`، تنظیم *پارامترهای حساس نشانی*…) |
| `{{form.id}}` · `{{form.field:NAME}}` | شناسه/نام فرم و مقدار یک فیلد. برای فیلدهای `password`، `email`، `tel`، `hidden` و `file` و نام‌های منطبق با `pass|mail|phone|mobile|tel|card|cvv|national|melli|nonce|token|secret` **رد می‌شود**. |
| `{{scroll.percent}}` · `{{time.seconds}}` | عمق اسکرول / ثانیه‌های دیده‌شدن صفحه |

مقداری که دقیقاً یک توکن باشد نوعش حفظ می‌شود (`{{page.post_id}}` عدد می‌ماند). توکن ردشده یا خالی، آن پارامتر را حذف می‌کند (در پنل اشکال‌زدایی پیداست).

<a id="s16-6"></a>

### ۱۶.۶ API پی‌اچ‌پی

برای اتفاقاتی که سمت سرور رخ می‌دهند (ورود، ثبت‌نام، پردازش فرم، webhook در درخواست بازدیدکننده). رویدادها برای بازدیدکنندهٔ فعلی (کوکی `wisetrack_sid`) صف و در بازدید صفحهٔ بعدی توسط مرورگر تحویل داده می‌شوند — یا بلافاصله پس از یک رویداد موفقیت AJAX ثبت‌شده با `wisetrack_pending_triggers`، یا وقتی JS شما `WiseTrackWP.pullPending()` را صدا بزند.

<div dir="ltr">

```php
wisetrack_track_event( string $name, array $params = [], array $args = [] ): bool;
// $args: 'revenue' => number, 'currency' => 'IRT', 'once_key' => string (queued once per visitor)
// Lower level (ServerEventQueue::track_event()): 'uid' => stable id [a-z0-9]{1,40} (the browser
// never sends two items with the same uid), 'ref' => internal reference passed to
// `wisetrack_server_events_acked`, 'sid' => queue for another visitor (e.g. from a webhook).

wisetrack_track_screen( string $name, array $args = [] ): bool;
// $args: 'display_name', 'type' (other|page|dialog|bottom_sheet|webview), 'params', 'once_key'

wisetrack_is_tracking_enabled(): bool; // configured and the current user's role is not excluded
```

```php
add_action( 'user_register', function ( $user_id ) {
	wisetrack_track_event( 'sign_up', [ 'method' => 'form' ], [ 'once_key' => 'signup:' . $user_id ] );
} );

add_action( 'my_plugin_order_paid', function ( $order ) {
	wisetrack_track_event( 'purchase', [ 'items' => $order->count ], [
		'revenue'  => $order->total,
		'currency' => 'IRT',
		'once_key' => 'order:' . $order->id,
	] );
} );
```

</div>

این توابع وقتی چیزی صف نشود `false` برمی‌گردانند: ردیابی غیرفعال، نام نامعتبر، `once_key` تکراری، یا عدم امکان تنظیم کوکی بازدیدکننده (headerها قبلاً ارسال شده‌اند — پیش از خروجی صدا بزنید). رضایت و DNT در مرورگر تعیین می‌شوند: آیتم‌های صف تا مجاز شدن SDK منتظر می‌مانند. محدودیت صف: ۵۰ آیتم و ۲۴ ساعت برای هر بازدیدکننده؛ آیتم‌های تأییدنشده پس از ۲ دقیقه دوباره تحویل داده می‌شوند.

| `wisetrack_updater_enabled` | `bool $enabled` | نسخهٔ private: بررسی GitHub Releases برای به‌روزرسانی |
| `wisetrack_update_repository` | `string $url` | نسخهٔ private: مخزن GitHub انتشارها |
| `wisetrack_updater_library` | `string $path` | نسخهٔ private: مسیر loader کتابخانهٔ Plugin Update Checker |

| اکشن | آرگومان‌ها | زمان |
|---|---|---|

### ۱۶.۱۰ لینک‌های انتخابگر دیداری

انتخابگر روی هر آدرس سایت با `?wisetrack_picker=1&_wpnonce=<nonce>` (اکشن nonce `wisetrack_picker`، وابسته به کاربر واردشده) برای کاربران دارای `manage_wisetrack` باز می‌شود؛ هر درخواست دیگری بدون این پارامترها به همان آدرس ریدایرکت می‌شود. لینک‌ها را با `WiseTrack\WP\Admin\Picker::url( $url, $extra )` بسازید:

| پارامتر | معنی |
|---|---|
| `wisetrack_rule=<id>` | باز کردن قانون برای ویرایش (selector آن با انتخاب بعدی جایگزین می‌شود) |
| `wisetrack_mode=existing` | شروع با «نمایش رویدادهای موجود» روشن |
| `wisetrack_origin=<token>` | توکن تب پیشخوانی که انتخابگر را باز کرده (در پیام‌ها برگردانده می‌شود) |

صفحه‌های انتخابگر نه runtime و نه SDK را بارگذاری می‌کنند، `nocache_headers()` و `X-Robots-Tag: noindex` می‌فرستند، `DONOTCACHEPAGE` را تعریف و نوار مدیریت را پنهان می‌کنند. پس از ذخیره (یا غیرفعال‌سازی)، انتخابگر پیام `{ type: 'wisetrack:rule-saved', rule, origin }` را روی `BroadcastChannel( 'wisetrack' )` و به `window.opener` (مقصد = origin پیشخوان) می‌فرستد تا صفحه‌های باز رویدادها به‌روز شوند.

### ۱۶.۱۲ نوشتن یکپارچه‌سازی اختصاصی

<div dir="ltr">

```php
use WiseTrack\WP\Integrations\AbstractIntegration;

class My_Booking_Integration extends AbstractIntegration {
	public function slug(): string { return 'my_booking'; }
	public function label(): string { return 'My Booking'; }
	public function category(): string { return 'forms'; }
	public function description(): string { return __( 'Confirmed bookings.', 'my-plugin' ); }
	public function is_available(): bool { return defined( 'MY_BOOKING_VERSION' ); }

	public function default_events(): array {
		return array( 'booked' => array( 'name' => 'booking_confirmed', 'label' => 'Booking confirmed' ) );
	}

	public function register(): void { // Only called when active and switched on.
		add_action( 'my_booking_confirmed', function ( $booking ) {
			$this->queue_event( 'booked', array( 'service' => $booking->service_slug ), array( 'once_key' => 'booking:' . $booking->id ) );
		} );
	}

	public function frontend_payload(): array { // Never visitor data (pages are cached); `pending` = client success signals.
		return array( 'pending' => array( 'my_booking_done' ) );
	}
}

add_filter( 'wisetrack_integrations', function ( $list ) {
	$list[] = new My_Booking_Integration();
	return $list;
} );
```

</div>

خروجی `frontend_payload()` در `WiseTrackWP.config.integrations[slug]` قرار می‌گیرد (فهرست `pending` آن در `config.pending`)؛ می‌تواند به URL وابسته باشد، هرگز به بازدیدکننده. اگر صفحه به `build/integrations.js` نیاز دارد `needs_frontend_script()` را override کنید. پلاگین‌های فرم می‌توانند از `WiseTrack\WP\Integrations\Forms\FormIntegration` ارث ببرند و `$this->submitted( $form_id, $form_name, $fields, $submission_id )` را صدا بزنند.

## ۱۷. ابزارها: برون‌بری، درون‌ریزی، بازنشانی، اطلاعات سیستم

| ابزار | توضیح |
|---|---|
| **برون‌بری** | فایل JSON شامل تنظیمات و قوانین؛ اطلاعات اتصال فقط با انتخاب گزینهٔ مربوط |
| **درون‌ریزی** | پیش‌نمایش تفاوت‌ها (رازها مخفی)، تعداد قوانین معتبر/نامعتبر، سپس اعمال. حداکثر ۲ مگابایت و ۱۰۰۰ قانون. فایل‌های نسخه‌های قدیمی‌تر مهاجرت داده و فایل‌های نسخهٔ جدیدتر رد می‌شوند. |
| **بازنشانی** | بازگرداندن تنظیمات پیش‌فرض (اطلاعات اتصال به‌صورت پیش‌فرض حفظ می‌شود) |
| **پنل اشکال‌زدایی** | روشن/خاموش برای همین مرورگر |
| **اطلاعات سیستم** | کپی نسخه‌ها، پلاگین‌های مرتبط و تنظیمات (بدون رازها) برای پشتیبانی |

**انتقال از staging به production:** برون‌بری در staging (بدون اطلاعات اتصال) ← درون‌ریزی در production ← وارد کردن اطلاعات اتصال production ← بررسی در Sandbox ← تغییر به Production.

## ۱۸. به‌روزرسانی، مهاجرت و حذف

### ۱۸.۱ به‌روزرسانی

- **نسخهٔ private** (`wisetrack-<version>-private.zip` از GitHub Releases) با [Plugin Update Checker](https://github.com/YahnisElsts/plugin-update-checker) (MIT، داخل `lib/`، با namespace نسخه‌دار) خودش را به‌روز می‌کند و مانند هر پلاگین دیگری در *پیشخوان › به‌روزرسانی‌ها* نمایش داده می‌شود. ثابت‌ها: [۱۶.۱۱](#s16)
- **نسخهٔ wp.org:** توسط WordPress.org به‌روز می‌شود؛ به‌روزرسان و گزینهٔ CDN ندارد.

<a id="s18-2"></a>

### ۱۸.۲ مهاجرت تنظیمات

تنظیمات نسخهٔ schema دارند (`Schema::VERSION`، فعلاً **3**). نسخهٔ نصب‌شدهٔ هر سایت در گزینهٔ `wisetrack_db_version` ذخیره می‌شود؛ در اولین درخواست پس از به‌روزرسانی، تنظیمات ذخیره‌شده گام‌به‌گام مهاجرت داده می‌شوند (حتی در به‌روزرسانی‌هایی که هوک فعال‌سازی را اجرا نمی‌کنند) و `wisetrack_upgraded` اجرا می‌شود. فایل‌های درون‌ریزی هم همین مراحل را طی می‌کنند: فایل‌های قدیمی‌تر درون‌ریزی و فایل‌های نسخهٔ جدیدتر رد می‌شوند.

| نسخه | تغییر |
|---|---|
| 1 ← 2 | جست‌وجو و ۴۰۴ از `smart_events.search` / `page_not_found` (buildهای 0.1) به یکپارچه‌سازی `wordpress` منتقل شدند |
| 2 ← 3 | مقصد تبدیل واحد `EHT` ← `ETH` (1.0.1) |

<div dir="ltr">

```php
// Your own migration on top of the built-in ones.
add_filter( 'wisetrack_migrate_settings', function ( $settings, $from ) {
	if ( $from < 2 && isset( $settings['naming'] ) && 'url' === $settings['naming'] ) {
		$settings['naming'] = 'path';
	}
	return $settings;
}, 10, 2 );
```

</div>

### ۱۸.۳ غیرفعال‌سازی / حذف

- **غیرفعال‌سازی:** ردیابی متوقف می‌شود؛ تنظیمات و قوانین حفظ می‌شوند.
- **حذف:** داده‌ها فقط وقتی پاک می‌شوند که *پیشرفته › حذف داده‌ها هنگام پاک کردن افزونه* روشن باشد (تنظیمات، قوانین، صف‌ها، قابلیت دسترسی).

## ۲۰. پرسش‌های متداول

**آیا با GDPR سازگار است؟** پلاگین ابزارها را فراهم می‌کند — حالت رضایت (پیش از رضایت SDK اصلاً بارگذاری نمی‌شود)، عدم ارسال اطلاعات شخصی، DNT/GPC، حذف پارامترهای حساس. انطباق نهایی به سایت و سیاست شما بستگی دارد.

**با پلاگین‌های کش کار می‌کند؟** بله. صفحه‌ها فقط دادهٔ وابسته به URL دارند و رویدادهای سرور از طریق یک فراخوانی REST با پرچم کوکی به مرورگر می‌رسند.

**مدیرها ردیابی می‌شوند؟** خیر، به‌صورت پیش‌فرض (*بازدیدکنندگان و حریم خصوصی › نقش‌های مستثنا*).

**فروشگاه من تومانی است؛ درآمد درست است؟** بله — تومان پیش از ارسال به ریال (×۱۰) تبدیل می‌شود؛ *تنظیمات › یکپارچه‌سازی‌ها › ووکامرس* نمونه‌ای با واحد پول خود شما نشان می‌دهد.

**خریدها دوبار شمرده می‌شوند / نمی‌آیند؟** هر سفارش یک‌بار و از مرورگر خریدار پس از پرداخت (یا در صفحهٔ تشکر) ارسال می‌شود. اگر خریدار پس از درگاهی که دیرتر تأیید می‌کند برنگردد، خرید در بازدید بعدی او تحویل داده می‌شود. یادداشت سفارش «WiseTrack: purchase event sent.» تحویل را تأیید می‌کند.

**بدون صفحهٔ رویدادها هم می‌شود ردیابی کرد؟** بله — ویژگی‌ها، کلاس‌ها، شورت‌کدها، API جاوااسکریپت یا پی‌اچ‌پی ([۱۶](#s16)).

**سایت را کند می‌کند؟** اثر قابل‌اندازه‌گیری بر LCP/CLS ندارد: runtime کمتر از ۱۲ کیلوبایت است و SDK پس از رندر به‌صورت async بارگذاری می‌شود.

|---|---|
| `wisetrack.php` | bootstrap و autoloader اختصاصی PSR-4 برای `WiseTrack\WP\` ← `includes/` |
| `includes/` | کد PHP (تنظیمات، ردیابی، قوانین، یکپارچه‌سازی‌ها، پیشخوان، REST) |
| `src/` | TypeScript: `runtime/` (بازدیدکننده)، `picker/`، `debug/`، `admin/`، `editor/`، `integrations/`، `shared/` (در تست‌های هم‌سانی PHP/JS) |
| `languages/` | POT، فایل‌های PO/MO/JSON فارسی، واژه‌نامه |
| `assets/vendor/wisetrack-sdk/` | بستهٔ SDK از npm (`bin/sync-sdk.sh <version>`) |
| `docs/` | مشخصات، نکات SDK، گزارش پیشرفت، روند انتشار (داخلی) |

### ۲۱.۳ تست و کیفیت

<div dir="ltr">

```bash
npm run lint             # ESLint, stylelint, tsc, PHPCS (WordPress-Extra/Docs/Security, PHPCompatibility)
composer phpstan         # PHPStan level 6
composer test            # PHPUnit unit tests (no WordPress)
npm run test:unit        # Jest
npm run test:php         # PHPUnit integration tests inside wp-env (WooCommerce, CF7, WPForms, Elementor loaded)
npm run test:e2e         # Playwright against the wp-env tests site
```

</div>

نمونه‌های PHP بخش‌های ۱۶ و ۱۸.۲ در نسخهٔ انگلیسی (`README.md`) توسط یک تست یکپارچه (`DeveloperDocsTest`) اجرا می‌شوند — همهٔ بلوک‌های `php` آن فایل باید قابل اجرا بمانند (فهرست امضاها و بلوک‌های `define()` نادیده گرفته می‌شوند).

محیط‌های دیگر: `node bin/wp-env-matrix.mjs 'WordPress/WordPress#6.2' 7.4 none` فایل `.wp-env.override.json` را می‌سازد، سپس `npm run env:start`. اسکریپت `bin/multisite-smoke.sh` سایت توسعه را به شبکه تبدیل می‌کند (فقط محیط دورریختنی).

### ۲۱.۴ ترجمه

`bin/make-pot.sh` فایل `languages/wisetrack.pot` را بازسازی، فایل‌های `.po` را به‌روز و فایل‌های `.mo` و JSON اسکریپت‌ها را می‌سازد. واژه‌نامهٔ فارسی: `languages/GLOSSARY.md`.

### ۲۱.۵ نسخه و انتشار

<div dir="ltr">

```bash
bin/sync-sdk.sh 2.3.2                              # refresh the bundled SDK (published npm package only)
bin/bump-version.sh --plugin 1.0.2 --sdk 2.3.3     # bump plugin and/or SDK version everywhere
bin/build-zip.sh private                           # or: wporg → dist/wisetrack-<version>-<flavor>.zip
bin/release.sh                                     # checks, both zips, publish to GitHub Releases
```

</div>

| Build | توزیع | به‌روزرسانی | منبع SDK |
|---|---|---|---|
| `private` | GitHub Releases ([`wisetrack-io/wordpress-plugin`](https://github.com/wisetrack-io/wordpress-plugin)) | به‌روزرسان داخلی | محلی (پیش‌فرض)، jsDelivr یا unpkg |
| `wporg` | WordPress.org | WordPress.org | فقط محلی |

`bin/build-zip.sh` هم‌خوانی نسخه‌ها، checksum فایل SDK، syntax کد PHP و نبود فایل‌های توسعه (و در `wporg` نبود کد به‌روزرسان/CDN) را بررسی می‌کند. مراحل انتشار، Plugin Check و راه‌اندازی مخزن عمومی در `docs/RELEASE.md` آمده است.
